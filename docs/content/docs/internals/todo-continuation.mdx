The agent keeps a todo list per workstream and the runtime auto-resumes it. When a turn ends with incomplete todos, the idle path injects a continuation prompt so the next pending item gets worked without the operator re-asking. The tools live in `src/agent/tools/todo/index.ts`; the engine that decides whether to nudge lives in `src/agent/todo/`. This page documents the load-bearing invariants — the operator never configures any of this, and there is intentionally no knob.

## The three tools

`createTodoTools` (`src/agent/tools/todo/index.ts`) returns three tools the model sees:

| Tool         | Shape               | Notes                                                             |
| ------------ | ------------------- | ----------------------------------------------------------------- |
| `todo_write` | `{ todos: Todo[] }` | **Full replace**, not a merge. The model re-sends the whole list. |
| `todo_read`  | `{}`                | Returns the current list — used to re-sync after an interruption. |
| `todo_clear` | `{}`                | Empties the list so the runtime stops tracking pending work.      |

A `Todo` is `{ content, status, priority?, id? }` where `status ∈ {pending, in_progress, completed, cancelled}` and `priority ∈ {high, medium, low}` (`src/agent/todo/store.ts`). "Incomplete" means `status` is neither `completed` nor `cancelled` (`incompleteTodos`); that set is what the engine counts.

Every tool resolves a scope first and **fails closed**: a session with no resolvable scope (subagent, system task, or undefined origin) gets a no-op plus the `NO_SCOPE_NOTICE`, never a write into someone else's list. An **undefined** origin is treated as no-scope — it is deliberately _not_ defaulted to the shared `tui` list, because defaulting would fail open and route an unknown actor's todos into the operator's global workstream.

A background `spawn_subagent` from a session that owns a scope and has no incomplete todos appends `SPAWN_TODO_REMINDER` to its tool result (`src/agent/tools/spawn-subagent.ts`): a runtime note asking the model to record what remains after the child finishes with `todo_write`. Delegated background work is the usual way a turn ends with steps still owed, and those steps survive a restart only as todos. The note is skipped for foreground spawns, for sessions without a scope, and when the list already has open items.

Both idle paths hold continuation while a background child spawned in the current turn is still running: the channel router through `isAwaitingBackgroundChild`, the TUI server through `newestRunningChildStartedAt`. The pending todo is usually the work that child is doing, so a nudge would only invite polling for a result that cannot exist yet; the child's completion reminder resumes the session instead. A child left running from an earlier turn does not hold it. If a held child settles without publishing a completion reminder (a work-key cancellation, for one), the TUI server runs the skipped decision once so the pending items are not stranded until the next prompt.

## Scope: the durable identity a list hangs off

A todo list is not keyed on `sessionId`. SessionIds churn — every TUI reconnect, every cron fire, and a channel session can roll to a fresh id after more than 60 minutes idle (`SESSION_FRESHNESS_TTL_MS`, `src/channels/router.ts`). Keying on the **origin identity** instead lets a list survive those transitions so interrupted work resumes. `resolveTodoScope` (`src/agent/todo/scope.ts`) maps a `SessionOrigin` to a `TodoScope` or `null`:

| Origin     | Scope                                           | Why                                                                                                      |
| ---------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `tui`      | singleton `tui`                                 | No stable per-operator identity; modeled as one global workstream. Concurrent attaches share it (below). |
| `channel`  | `channel/<adapter>:<workspace>:<chat>:<thread>` | Matches how `channels/sessions.json` identifies a conversation. Survives restart and stale-rollover.     |
| `cron`     | `cron/<jobId>`                                  | The sessionId is fresh every fire; the job is the durable identity.                                      |
| `subagent` | `null`                                          | Subagents do not own continuation — their parent does.                                                   |
| `system`   | `null`                                          | Runtime infrastructure (memory/backup) is not user-delegated work and must never auto-continue.          |

`scope.key` is a **traversal-safe relative key**, not a single path segment: the `channel/...` and `cron/...` keys deliberately contain `/` and are stored as nested paths under `todo/`. What is single-segment-safe is each encoded **component** within a key. `encodeComponent` emits a discriminant prefix (`n` for null, `s<encodeURIComponent(value)>` for strings) so the cases lossy schemes confused stay pairwise distinguishable: a null thread vs a literal `"n"`, an empty string vs `"_empty"`, and any two values whose unsafe chars would otherwise collide. `encodeURIComponent` never emits `/` or `:`, so each component is a clean path-segment and the joined key is a collision-free conversation identity whose only `/` separators are the ones the scheme intends.

### Storage

`todoContentPath` writes to `<agentDir>/todo/<scope.key>.json`; continuation state goes to `<agentDir>/todo/.state/<scope.key>.json` (`continuation-state.ts`). Both writers are atomic (temp file + `rename`), mirroring `channels/sessions.json`, so a crash mid-write can't leave half-serialized JSON the next read throws on. `todoContentPath` re-asserts the resolved path stays inside `todo/` as defense-in-depth — even though `resolveTodoScope` already produces traversal-safe keys, the path builder is an exported primitive and must not trust a hand-built scope like `{ key: '../sessions/x' }`.

The `todo/` directory is **system-managed**: gitignored so the agent doesn't stage it by hand, but force-committed by typeclaw on its own schedule (`src/init/gitignore.ts`), same category as `sessions/` and `memory/`. Because the files are force-committed and hand-editable, `readTodos` drops any malformed entry rather than trust it — a corrupt item never crashes `incompleteTodos` or surfaces as trusted state to the model.

## The continuation engine

`decideContinuation` (`src/agent/todo/continuation-policy.ts`) is a pure function: given the persisted state, the current todos, the last turn outcome, and `now`, it returns `inject` (with the episode to persist) or `skip` (with a reason). It **fails closed on every ambiguity**.

### Episodes and budgets

A continuation **episode** is the unit a budget applies to. It opens when the first auto-nudge fires after a real user turn (or restart recovery) and resets **only on the next real user prompt** — never on the runtime's own injected prompts. The episode is persisted so budgets survive a restart: a crash-loop cannot reset the ceiling. Four budgets, all defaults in `continuation-policy.ts`:

| Budget                | Default  | Skip reason      |
| --------------------- | -------- | ---------------- |
| `maxAutoTurns`        | `3`      | `max-auto-turns` |
| `maxCumulativeTokens` | `20_000` | `max-tokens`     |
| `maxWallClockMs`      | `30 min` | `max-wall-clock` |
| `stagnationLimit`     | `2`      | `stagnation`     |

The budget counts **output tokens**: `lastTurnOutcome.tokens` is the final assistant message's `usage.output`. Input and cache counts re-bill the whole context on every request, so they track context size and provider caching rather than the work a turn did; with them, one ordinary turn exhausted the budget. Output is charged to the open episode's `cumulativeTokens` as each assistant message's outcome is recorded (`onTurnOutcome`), and **only when todo continuation started that turn** (`continuationTurn`), so continuation spend counts even when a later idle skips instead of injecting. The channel router tags its nudge reminder and marks a turn whose prompt carries nothing but that nudge; the TUI server marks turns whose queued item came from continuation. The user turn that opens an episode, a background-completion wakeup that lands inside one, and a prompt that mixes the nudge with fresh input or another reminder are never charged. Missing usage counts as 0.

Separately from the episode budgets, a list whose file was last written 72 hours ago or more (`maxListAgeMs`) is skipped as `stale-list`. `writeTodos` stamps `updatedAt` on every write; a file with no stamp (written before stamps existed) counts as stale. Lists that get worked again are touched within the hour almost every time, so an older list is abandoned work in a conversation that has moved on.

### Stagnation: hash-equality, not real progress

`hashIncomplete` canonicalizes the incomplete set (sort by id-or-text, collapse whitespace, include status) into a stable SHA-256. The live gate in `decideContinuation` is hash equality: when `episode.lastIncompleteHash === hash` the turn is **stagnant** and `stagnationCount` increments; two consecutive stagnant turns (`stagnationLimit`) end the episode. Because the hash normalizes order and whitespace, a pure reorder or whitespace-only edit reads as stagnant — but a genuine **reword or split changes the hash and so resets the counter**, even though no item was completed. The hash is a _heuristic_, not proof of progress.

`hasRealProgress` (incomplete set must **shrink**) is the stricter shrink-only test the file documents as the "fake-progress" closer, but it is **not wired into `decideContinuation`** today — it exists with unit coverage and is unused by the runtime decision. Treat the hash-equality gate as the real behavior; `hasRealProgress` is a latent helper, not the enforced invariant.

### The skip ladder

`decideContinuation` checks in order, first match wins:

1. **`no-incomplete-todos`** — nothing left to do.
2. **`stale-list`** — the list was last written `maxListAgeMs` (72 hours) ago or more, or has no recorded write time.
3. **`restart-kick-suppressed`** — the one-shot restart suppressor is armed (below).
4. **`user-abort-blocked`** — the durable user-abort suppressor is set (policy D1).
5. **`turn-not-safe`** — the last outcome is missing, `error`, `unknown`, or an unproven `aborted`. The sole safe abort is a successful terminal `channel_reply` carrying runtime-owned `termination: 'terminal-after-channel-reply'` provenance; the raw stop reason remains `aborted`. `unknown`, missing, stale, and malformed provenance all fail closed. `error` has no exception, even with terminal-reply provenance (see below).
6. **`delivered-after-todo-write`** — the channel turn delivered a message after its last `todo_write` (below).
7. **`max-auto-turns` / `max-tokens` / `max-wall-clock`** — a budget ceiling tripped.
8. **`stagnation`** — `stagnationCount` hit the limit.

Only after all eight pass does it return `inject` with `autoTurnCount + 1`.

After the policy, `maybeInjectContinuation` changes an `inject` decision to **`watch-pending`** only if every incomplete todo's exact `content` matches the `waitsFor` of an active watch targeting this conversation. Channel watches match by conversation key; any TUI watch matches the shared TUI scope. If any incomplete item lacks a matching active watch, continuation proceeds as normal. Paused and unlinked watches, including auto-registered watches, do not count. The skip logs `todo_continuation skip reason=watch-pending` and does not write an episode or spend continuation budget. See [Watches](/docs/internals/watches).

The next delivered or permission-denied wake clears the link, even if the watch stays active. A denied wake is discarded without prompting; the next ordinary idle can take up the todo. TUI idle waits for delivery acknowledgment. In channels, after a continuation-safe, silent isolated watch turn, the router restores ordinary turn state and evaluates continuation once as the last ordinary speaker, using the usual policy and budgets. A failed watch turn or one that delivered a reply does not trigger that decision. The channel session record preserves that speaker's ID, adapter, and parent-chat context across eviction. If the speaker is unavailable or no longer authorized to respond, the router does not borrow the watch requester's authority. Cancelling a linked watch from another conversation queues a final wake to the original target; cancellation in the target conversation needs no extra turn. If a child of that watch lineage is still running or its result has not been handled, only the linked todo is parked; unrelated runnable todos can still continue. The todo-to-watch association follows the completion reminder across reloads. Eligibility is recalculated from the durable child obligation, so a closed or transferred result cannot keep the todo parked. A user stop clears the association. A clean, silent completion can trigger the ordinary decision once. If the last child result is denied or otherwise closed without a prompt, its todo becomes eligible again without an immediate nudge or result replay. A delivered watch reply hands back its linked todo until fresh ordinary human input in that conversation; other runnable todos remain eligible.

### A turn that hands back a message does not continue

Continuation exists for a turn that **stops silently** with work left. A channel turn that delivers output (a channel message or a formal GitHub review) after its last `todo_write` (or, with no `todo_write` that logical turn, at all) has handed the turn back to the person, so the router records `deliveredAfterTodoWrite: true` on its outcome and the idle skips with `delivered-after-todo-write`. Replaying stranded channel turns showed nudges after a delivered message mostly produced early or repeated posts about work still waiting on a scheduled check, a restart, or a background result, while silent stops were the ones a nudge helped. A `channel_reply` that renews a promise to keep working (`continue_after_reply: true`) does not count as handing back.

The router counts delivered output per session (`deliveredOutputs`: successful sends plus formal reviews), marks it at each successful `todo_write` and at the start of the logical turn, and compares at idle, inside the serialized decision chain (`recordTurnHandBack`). Recording at idle rather than when the outcome is written matters: reply recovery can deliver a turn's final prose after its last assistant message ends. A terminal `channel_reply` always hands back, so terminal-reply provenance no longer leads to a nudge; it still keeps that runtime-owned abort from arming the user-abort block. TUI turns are unaffected: they record no deliveries.

### Failed turns do not auto-continue

When the last recorded outcome is `stopReason: 'error'` — the turn's final assistant message failed, whether from the provider or from the runtime while preparing the request — the idle path skips with `turn-not-safe`. Injecting a continuation would send the same conversation straight back into the request that just failed, and each failed nudge would spend an auto-turn on nothing. `length` stays continuation-eligible and `stop` is unchanged; only the final failure blocks.

The scope is deliberately narrow:

- **TUI and channel sessions alike.** These are the two idle paths that call `runIdleContinuation`; both record outcomes through `recordTurnOutcome` and decide through the same `decideContinuation`. Cron has no idle continuation driver, and subagent/system sessions own no todo scope.
- **Retries inside the turn still run.** Same-model retries and fallbacks the turn already attempts are untouched. Outcomes are recorded from each assistant `message_end`, so when a retry lands a successful message its outcome replaces the `error` and the idle continues normally.
- **Not durable.** There is no failure counter and no suppressor; the skip is decided from the latest outcome alone and does not touch the episode. The next real user turn resets the episode as usual, records a fresh outcome, and can drive the remaining todos again.

### Suppressors

Two suppressors live in `ContinuationState` and gate injection independent of budget:

- **Restart-kick** (`suppressNextIdleNudgeReason: 'restart-kick'`) — a one-shot. The post-restart kick prompt owns the first idle, so the first idle after a restart consumes this and skips exactly one injection. It is consumed even on a skip, so the suppressor always burns exactly once (`maybeInjectContinuation`, `consumeRestartKickSuppression`).
- **User-abort** (`autoResumeBlockedUntilRealUserTurn`) — durable. Set when a turn ends via explicit user abort (`onTurnOutcome` on `stopReason: 'aborted'`); cleared only by the next real user turn (`onTurnStart`). While set, no auto-continuation fires regardless of budget. The runtime's turn-stamped terminal-`channel_reply` provenance is the narrow exception because that abort intentionally suppresses a redundant post-tool model call after the reply has landed. `/stop` synchronously supersedes that provenance and serializes an untrusted aborted outcome after any pending outcome write, so it remains binding even when the terminal outcome was already captured. The continuation decision itself joins that same chain, so a `/stop` landing mid-decision cannot have its durable abort clobbered by the decision's own state write, and the stop marker is re-read at delivery so an already-decided reminder is dropped rather than enqueued. Every unproven abort still arms the block, so a user who hits stop is not second-guessed by the runtime.

### Fail-closed state parsing

`parseContinuationState` validates the persisted file field-by-field and collapses anything malformed to its empty value rather than trusting it. A partially-written file or a schema skew must never surface an `episode` whose `undefined`/`NaN` counters would compare false against the ceilings and bypass the token-burst guard: a malformed episode collapses to `null` (a fresh episode opens next decision); a malformed outcome collapses to `null` (the idle path then fails closed).

## Wiring

`src/agent/todo/continuation-wiring.ts` is the seam between the engine and the per-origin drain loop:

- **`recordTurnStart`** resets the episode at the start of a **real** user turn. Injected continuation turns pass `isRealUserTurn=false` so the budget keeps counting down. No-op for scopeless origins.
- **`recordTurnOutcome`** persists the just-completed turn's `stopReason` + `tokens` from a pi `message_end` event. Channel sessions also attach one-shot terminal-reply provenance only when the raw outcome is `aborted` and the router's abort stamp matches the current turn. In both TUI and channel sessions, per-session writes are serialized on a recoverable tail, so an older outcome can never land after a newer one, while each tail value separately reports whether its write succeeded. The drain waits for the latest tail before `recordTurnStart` and again before the idle decision, and skips continuation when that latest write failed instead of consulting stale eligible state. The TUI drain re-checks its queue after that wait, so a real user prompt that arrived meanwhile runs first. The idle decision itself is chained onto the same tail, so an outcome write that starts during the decision (an abort) lands after the decision's own state write. `classifyStopReason` maps anything unrecognized to `unknown` so the idle path fails closed; `extractTurnUsage` only reads assistant `message_end` events.
- **`armRestartKickForOrigin`** arms the one-shot before a restart kick.
- **`runIdleContinuation`** is the idle-path entry: it calls `maybeInjectContinuation` (decide + persist) and, on `injected`, delivers the `CONTINUATION_PROMPT` via the origin-appropriate mechanism the caller supplies (TUI `stream.publish`; channel `pendingSystemReminders` + drain). Its `onDecision` callback lets both drivers write one operator-log line per idle with pending work: `todo_continuation inject` or `todo_continuation skip reason=<reason>` (`describeContinuationDecision`). Idles with no pending work log nothing. These lines count **policy evaluations**: the channel router's pre-policy exits (a failed outcome write, a user stop, a background child spawned this turn still running) never reach the policy and keep their own log lines.

The episode mutation is persisted **before** delivery, so a crash between persist and deliver can only **under**-count — a missed delivery wastes one budget slot, never an unbounded loop. The injected `CONTINUATION_PROMPT` (`continuation.ts`) is a fenced `**[SYSTEM MESSAGE — not from a human]**` block — the same convention as the [engagement](/docs/internals/engagement) loop-guard and group-chat notices — that tells the model to work the next item, verify completed work skeptically before asserting done, and call `todo_clear` when genuinely finished.

## Rules of thumb

- **`decideContinuation` is pure and fails closed.** Every ambiguous input yields `skip`. If you add a budget or a suppressor, add it to the skip ladder _and_ to `parseContinuationState`, or a malformed state file will bypass it.
- **Only a real user turn resets the episode.** The runtime's own injected prompts pass `isRealUserTurn=false`. Reset on an injected turn and the budget never counts down — the crash-loop ceiling is gone.
- **Stagnation is hash-equality, not shrink.** The live gate is `lastIncompleteHash === hash`; a reword or split resets it even with no item completed. `hasRealProgress` (shrink-only) is a stricter helper that exists but is **not** wired into the decision — don't describe it as the enforced behavior, and if you wire it in, update this page.
- **No-scope is a no-op, not a default.** Subagent / system / undefined origins own no list. Never default an unknown origin into the `tui` scope.
- **Persist before deliver.** The under-count failure mode (one wasted slot) is the safe one. Never reorder to deliver-then-persist, which can double-inject after a crash.
- **TUI is a documented singleton.** Concurrent TUI attaches share one `tui` scope; last-writer-wins on the atomic rename is accepted (no lock for a todo list).
