---
title: Watch tool
description: Follow an external job without starting an agent turn on every check.
---

Use `watch` when the question is “has anything happened that needs attention?” Use cron when the work must happen at a particular time regardless of external state.

```json
{
  "action": "create",
  "description": "Report when the export is available",
  "probe": { "command": "if test -f workspace/export.csv; then echo 'Export ready'; exit 30; fi" },
  "deadline": "2d"
}
```

`create` returns an `id`. `list` shows watches in the caller's conversation (all watches for the owner). Use `cancel` with an `id` to stop a live watch or `rearm` to resume a paused one. `create` and `rearm` require `watch.create`, granted by default to owner, trusted and member. Deadlines are relative durations, default 14 days, maximum 30 days.

**Judge mode** (default): exit `0` for quiet, `10` to wake, `20` to finish silently or `30` to finish and wake. Stdout supplies the summary; alternatively end stdout with JSON such as `{"verdict":"wake","summary":"Export needs credentials","next":"15m"}`. A JSON `done` verdict ends silently unless it includes `"wake":true`. Deadline expiry always sends a final reminder. Other exits are failures. A command can specify `cwd`. Make side effects idempotent: execution is at least once, not exactly once.

**Waiting on a todo:** On `create`, set `waitsFor` to the exact content of a pending todo in this conversation, for example `"waitsFor": "Review the export"`, only if the item cannot progress until the watch reports. Todo continuation parks only when every incomplete item is linked to an active watch that wakes the conversation. An unlinked item can still continue, and paused or automatically registered watches do not count. The next delivered or permission-denied wake clears the link even if the watch keeps running. A denied wake does not start a turn. If you still need to wait, create another watch with `waitsFor`.

A still-linked watch wakes on completion even for exit `20` or a JSON `done` without `"wake":true`. Cancelling it from another conversation sends a final reminder to its original target. Cancelling in the target conversation is quiet.

**Diff mode**: set `"mode":"diff"` for a command whose stable stdout is the state of interest. The first successful output establishes a baseline; subsequent changes wake with a unified diff. Do not use diff for multi-step statuses where most transitions require no action.

## GitHub follow-up

The bundled `github-pr` and `github-issue` probes take a GitHub.com repository slug and a positive PR or issue number. They use judge mode and do not run shell commands.

```json
{
  "action": "create",
  "description": "Follow up on PR acme/widgets#12",
  "probe": { "bundled": "github-pr", "target": { "repo": "acme/widgets", "number": 12 } }
}
```

- `github-pr` wakes for a new failing check set on the current head, once per head when checks have passed, for a new approval or change request from someone else, for new comments or review comments by others, or when the PR becomes conflicting. Pending checks alone are quiet. Pre-watch approvals are quiet, but an outstanding current-head change request can wake on the first poll. Merge or closure ends the watch and wakes the agent.
- `github-issue` wakes for new comments by others. Closure ends the watch and wakes the agent with the close reason.

By default, a successful model `bash` call that opens a PR or issue through a supported `gh pr create`, `gh issue create`, or `gh api` create registers the corresponding bundled watch. Viewing and listing do not. Registration requires `watch.create`, skips targets with an existing live watch, and includes the new watch ID in the bash result. Use that ID with `watch cancel` if follow-up is not needed. Set `"watches": { "auto": false }` in `typeclaw.json` to disable automatic registration without affecting existing watches or manual creation. The setting takes effect on reload.

Automatic registration also requires a polling credential authorized for the caller and repository. An imported host `gh` login can fund the create command, but not unattended polling. If that is the only credential available, the bash result says no follow-up watch was scheduled. Configure GitHub App auth for the repository or an authorized PAT before creating a bundled watch manually.

## Wake delivery

TUI wakes wait for an attached, idle TUI. Reconnecting opens a new session but still receives pending wakes; they stay pending until a turn starts. Channel wakes return to the original conversation, even if its session has gone cold. If the adapter’s account is not ready, delivery retries. If the requester no longer has `channel.respond`, the wake is logged but not posted. The probe result is a private reminder to the agent; only its reply reaches the conversation. That reply does not make the agent engage with subsequent messages. Unattended watches without a human ancestor start a fresh slim session.
