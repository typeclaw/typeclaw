## Host stage

| Variable                   | Read by    | Default       | Effect                                                                                                            |
| -------------------------- | ---------- | ------------- | ----------------------------------------------------------------------------------------------------------------- |
| `TYPECLAW_HOME`            | hostd, CLI | `~/.typeclaw` | Override the host daemon state directory; primarily for tests                                                     |
| `TYPECLAW_LOG_LEVEL`       | CLI        | `info`        | `debug` / `info` / `warn` / `error`                                                                               |

### Model-driven bash environment

Every production model-driven bash call runs in bwrap with the inherited process environment cleared, including for `trusted` and `owner`. TypeClaw adds back the sandbox-owned allowlist plus **every var an operator declared in `.env` except runtime-owned `TYPECLAW_*` controls**. The only process-environment exception is the four Git identity variables above: a fresh container resolves them from the local `user.name`/`user.email` pair in the agent repository, and model bash inherits them so new clones keep that identity. The runtime-resolved pair overrides same-named `.env` values and Git's sanitized generated config; restart the TypeClaw container after changing the agent repo identity. When either key is missing, `typeclaw start` writes it to the agent repo's local config from the agent folder name (`<folder>` and `<folder-slug>@typeclaw.local`), so runtime commits never lose their identity; values you set are never overwritten. That fallback stays in repo config and is not exported as these variables, so an identity set later (for example during hatching) applies without a restart. `.env` is otherwise the deliberate expose-to-the-agent surface, so ordinary values you put there (including `GH_TOKEN`/`GITHUB_TOKEN`, e.g. so plain `gh`/`git`/`curl` work in agents with no GitHub channel) reach model bash. The model-HTTP policy variables above are withheld and raw live `.env` remains canonically masked from every file tool and bash role. Credentials you do not want the agent to read must live in `secrets.json`, which is never inherited into bash. Preserving PR #1256, `.env` remains excluded from the Git metadata contamination list: knowing historical policy strings does not grant authority to alter the immutable boot policy, so `.env` in history alone never disables model bash. Runtime-owned credential overlays, such as a per-repo GitHub token minted by the `github-cli-auth` broker for a validated `gh` call, are injected directly into one narrowly parsed subprocess; they do not make `.env`, `secrets.json`, or historical root `auth.json` readable. GitHub token-display and auth-management commands, including `gh auth status -t` and `--show-token`, are blocked before injection.

### Model HTTP internal destination policy

`TYPECLAW_MODEL_HTTP_ALLOW_INTERNAL_HOSTS` and `TYPECLAW_MODEL_HTTP_ALLOW_INTERNAL_CIDRS` are parsed once when the container runtime boots. Each is either unset/empty or a comma-separated list of at most 64 entries. Empty entries and malformed values fail boot. Host entries are exact, case-insensitive, IDNA-normalized names; wildcards, suffix patterns, URLs, and IP literals are rejected. CIDRs require an explicit IPv4 or IPv6 prefix, for example `10.20.0.0/16,fd12:3456::/48`.

The policy applies only to the safe HTTP transports behind `web_fetch` and URL-backed `look_at`. It does not weaken DNS answer validation, socket pinning, mixed-answer fail-closed behavior, redirect revalidation, or cross-origin credential stripping. Cloud metadata and control-plane endpoints remain unconditionally blocked, including Azure WireServer and their IPv4 forms embedded in IPv4-compatible/mapped/translatable IPv6, the well-known `64:ff9b::/96` NAT64 prefix, and 6to4 `2002::/16`. The entire RFC 8215 local-use translation prefix `64:ff9b:1::/48` is also non-overridable: RFC 8215 is technology-agnostic and applications cannot safely infer where, or whether, an IPv4 address is embedded, so TypeClaw cannot distinguish metadata translations from other members before applying exceptions. This does not claim that every member maps metadata. Coverage is deliberately bounded to these standardized ranges and forms; arbitrary operator-specific RFC 6052 prefixes are not inferred. Changing these values requires a container restart; `typeclaw reload` does not read them. With `network.blockInternal: true`, private IPv4 access generally also needs a narrow `typeclaw.json#network.allow` entry for the separate container firewall.

No model-driven role receives reusable Codex, Claude, GWS, or agent-messenger auth files. Those CLIs can upload arbitrary files, so even a standalone-command parser would make them confused deputies. They run with the cleared environment and no auth profile; version/help and unauthenticated diagnostics remain available. Standalone local Git commands may receive a generated config containing only `user.name` and `user.email`; the original config is never mounted. When the container also has the runtime-resolved author/committer variables above, Git gives those environment values precedence over the generated config.

## Provider credentials

Set in the host stage; injected into the container via `--env-file .env`.

These env vars override a stored API-key credential in `secrets.json` (env-wins). The exception is dual-auth providers (`anthropic`, `xai`): a stored OAuth credential takes precedence over the env var, since OAuth is stateful and refreshed on disk. See [/concepts/secrets-policy](/docs/concepts/secrets-policy) for the full resolution order.

| Variable                  | Provider          | Notes                                                                                                    |
| ------------------------- | ----------------- | -------------------------------------------------------------------------------------------------------- |
| `FIREWORKS_API_KEY`       | `fireworks`       |                                                                                                          |
| `OPENAI_API_KEY`          | `openai`          |                                                                                                          |
| `ANTHROPIC_API_KEY`       | `anthropic`       | OAuth credential on disk wins over this env var (dual-auth provider).                                    |
| `ZAI_API_KEY`             | `zai`             | Z.AI pay-as-you-go.                                                                                      |
| `ZAI_CODING_API_KEY`      | `zai-coding`      | Z.AI GLM Coding Plan — separate billing surface from `zai`.                                              |
| `XAI_API_KEY`             | `xai`             | xAI (Grok). OAuth credential on disk wins over this env var (dual-auth provider).                        |
| `MINIMAX_API_KEY`         | `minimax`         | Accepts either a pay-as-you-go API key or a Token Plan Subscription Key (`sk-cp-…`) — same slot.         |
| `DEEPSEEK_API_KEY`        | `deepseek`        | DeepSeek pay-as-you-go.                                                                                  |
| `UPSTAGE_API_KEY`         | `upstage`         | Upstage (Solar) pay-as-you-go. Keys are prefixed `up_`.                                                  |
| `MOONSHOT_API_KEY`        | `moonshot`        | Moonshot (Kimi) Open Platform pay-as-you-go.                                                             |
| `MOONSHOT_CODING_API_KEY` | `moonshot-coding` | Kimi Code subscription — separate billing surface from `moonshot`.                                       |
| `OPENGATEWAY_API_KEY`     | `opengateway`     | OpenGateway multi-vendor gateway. One key reaches every upstream it fronts.                              |
| `INCEPTION_API_KEY`       | `inception`       | Inception (Mercury) pay-as-you-go.                                                                       |
| (others)                  |                   | Each known provider has a canonical env var; see [/reference/secrets-json](/docs/reference/secrets-json) |

Custom env-var names are supported via the `Secret`'s `env` field — `{ "key": { "env": "MY_OPENAI" } }`. See [/concepts/secrets-policy](/docs/concepts/secrets-policy) for resolution order.

## Provider endpoint overrides

Set in the host stage; injected into the container via `--env-file .env`.

| Variable             | Provider    | Default                     | Effect                                                            |
| -------------------- | ----------- | --------------------------- | ----------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL` | `anthropic` | `https://api.anthropic.com` | Point the Anthropic provider at an Anthropic-compatible endpoint. |
| `OPENAI_BASE_URL`    | `openai`    | `https://api.openai.com/v1` | Point the OpenAI provider at an OpenAI-compatible endpoint.       |

`ANTHROPIC_BASE_URL` routes the `anthropic` provider through a proxy that speaks the **native Anthropic Messages protocol** (`/v1/messages`, `x-api-key` or OAuth Bearer) — e.g. LiteLLM, Cloudflare AI Gateway, or a corporate gateway. It is a base-URL swap only; it does **not** enable raw AWS Bedrock, which requires SigV4 signing and a different request path.

`OPENAI_BASE_URL` does the same for the `openai` provider, routing it through an **OpenAI-compatible** endpoint (LiteLLM, Azure-style gateways, corporate proxies). It targets the api-key `openai` provider only — the OAuth-only `openai-codex` ChatGPT backend is unaffected.

Both follow the same rules: trailing slashes are stripped; a non-http(s) value fails the agent at boot. The same endpoint is used by `typeclaw init`'s API-key validation probe.
